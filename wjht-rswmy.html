    5. واجهات رسومية

    نقترح هنا عرض كيفية إنشاء واجهات رسومية باستخدام JAVA. سنرى أولاً ما هي الفئات الأساسية التي تسمح لنا بإنشاء واجهة رسومية. لن نستخدم في البداية أي أداة للتوليد التلقائي. ثم سنستخدم JBuilder، وهي أداة تطوير من Borland/Inprise تسهل تطوير تطبيقات Java ولا سيما إنشاء الواجهات الرسومية.

    5.1. أساسيات الواجهات الرسومية

    5.1.1. نافذة بسيطة

    لننظر إلى الكود التالي:

    
// الفئات المستوردة
import javax.swing.*;
import java.awt.*;
    
    // فئة النموذج
  public class form1 extends JFrame {
    
      // المنشئ
      public form1() {
            // عنوان النافذة
            this.setTitle("Mon premier formulaire");
            // أبعاد النافذة
            this.setSize(new Dimension(300,100));
      }//المنشئ
  
      // وظيفة الاختبار
      public static void main(String[] args) {
            // يتم عرض النموذج
            new form1().setVisible(true);
      }
  }//الفئة

    يؤدي تنفيذ الكود السابق إلى عرض النافذة التالية:

    عادةً ما تُشتق واجهة المستخدم الرسومية من الفئة الأساسية JFrame:

    
  public class form1 extends JFrame {

    تحدد الفئة الأساسية JFrame نافذة أساسية مزودة بأزرار للإغلاق والتكبير/التصغير وحجم قابل للتعديل، وما إلى ذلك... وتدير الأحداث على هذه الكائنات الرسومية. هنا نقوم بتخصيص الفئة الأساسية عن طريق تحديد عنوان لها وعرضها (300 بكسل) وارتفاعها (100 بكسل). يتم ذلك في منشئها:

    
      // المنشئ
      public form1() {
            // عنوان النافذة
            this.setTitle("Mon premier formulaire");
            // أبعاد النافذة
            this.setSize(new Dimension(300,100));
      }//المنشئ

    يتم تحديد عنوان النافذة بواسطة الطريقة setTitle وأبعادها بواسطة الطريقة setSize. تقبل هذه الطريقة كمعلمة كائن Dimension(largeur,hauteur) حيث largeur و hauteur هما عرض وارتفاع النافذة بالبكسل.

    تقوم الطريقة main بتشغيل التطبيق الرسومي بالطريقة التالية:

    
            new form1().setVisible(true);

    يتم بعد ذلك إنشاء نموذج من النوع form1 (new form1()) وعرضه (setVisible(true))، ثم يبدأ التطبيق في الاستماع إلى الأحداث التي تحدث على النموذج (النقرات، تحركات الماوس، ...) ويقوم بتنفيذ الأحداث التي يديرها النموذج. هنا، لا يدير نموذجنا أحداثًا أخرى غير تلك التي تديرها الفئة الأساسية JFrame (النقرات على أزرار الإغلاق، التكبير/التصغير، تغيير حجم النافذة، تحريك النافذة، ...).

    عند اختبار هذا البرنامج عن طريق تشغيله من نافذة DOS باستخدام:

    java form1

    لتنفيذ الملف form1.class، نلاحظ أنه عند إغلاق النافذة التي تم عرضها، لا "نستعيد السيطرة" في نافذة DOS، كما لو أن البرنامج لم ينته. وهذا هو الحال بالفعل. يتم تنفيذ البرنامج على النحو التالي:

    • في البداية، يتم تشغيل مؤشر ترابط أول لتنفيذ الأسلوب main
    • وعندما تقوم هذه الطريقة بإنشاء النموذج وعرضه، يتم إنشاء مؤشر ترابط ثانٍ لإدارة الأحداث المرتبطة بالنموذج على وجه التحديد
    • بعد هذا الإنشاء، وفي مثالنا هذا، ينتهي مؤشر الترابط الخاص بالطريقة main ويبقى فقط مؤشر الترابط الخاص بواجهة المستخدم الرسومية.
    • عند إغلاق النافذة، تختفي هذه الأخيرة ولكنها لا توقف الخيط الذي كانت تعمل فيه
    • ونحن مضطرون في الوقت الحالي لإيقاف هذا الخيط بالضغط على Ctrl-C في نافذة DOS التي تم من خلالها تشغيل البرنامج.

    دعونا نتحقق من وجود خيطين منفصلين، أحدهما يتم فيه تنفيذ الطريقة main، والآخر يتم فيه تنفيذ النافذة الرسومية:

    
// الفئات المستوردة
import javax.swing.*;
import java.awt.*;
import java.io.*;

// فئة النموذج
 public class form1 extends JFrame {
    
// المنشئ
 public form1() {
   // عنوان النافذة
   this.setTitle("Mon premier formulaire");
   // أبعاد النافذة
   this.setSize(new Dimension(300,100));
}//المنشئ
  
// وظيفة الاختبار
 public static void main(String[] args) {
   // المتابعة
   System.out.println("Début du thread main");
   // يتم عرض النموذج
   new form1().setVisible(true);
   // المتابعة
   System.out.println("Fin du thread main");  
}//يدوي
}//فئة

    يؤدي التنفيذ إلى النتائج التالية:

    يمكن ملاحظة أن مؤشر الترابط main قد انتهى بينما لا تزال النافذة معروضة. لا يؤدي إغلاق النافذة إلى إنهاء مؤشر الترابط الذي كان يعمل فيه. لإيقاف مؤشر الترابط هذا، نضغط مرة أخرى على Ctrl-C في نافذة DOS.

    لإنهاء هذا المثال، نلاحظ الحزم المستوردة:

    • javax.swing للفئة JFrame
    • java.awt للفئة Dimension

    5.1.2. إدارة حدث

    في المثال السابق، يتعين علينا إدارة إغلاق النافذة بأنفسنا حتى نتمكن من إيقاف التطبيق عند حدوث ذلك، وهو ما لم يتم حتى الآن. ولهذا الغرض، يتعين علينا إنشاء كائن "يستمع" إلى الأحداث التي تحدث على النافذة ويكتشف حدث "إغلاق النافذة". يُطلق على هذا الكائن اسم "المستمع" أو مدير الأحداث. توجد أنواع مختلفة من المديرين للأحداث المختلفة التي قد تحدث على مكونات واجهة المستخدم الرسومية. بالنسبة للمكون JFrame، يُسمى المستمع WindowListener وهو واجهة تحدد الطرق التالية (انظر وثائق Java)

    ملخص الطرق
    		 
    void
    windowActivated(WindowEvent e)
              تصبح النافذة هي النافذة النشطة
    		 
    void
    windowClosed(WindowEvent e)
              تم إغلاق النافذة
    		 
    void
    windowClosing(WindowEvent e)
              طلب المستخدم أو البرنامج إغلاق النافذة
    		 
    void
    windowDeactivated(WindowEvent e)
              لم تعد النافذة هي النافذة النشطة
    		 
    void
    windowDeiconified(WindowEvent e)
              تنتقل النافذة من الحالة المصغرة إلى الحالة العادية
    		 
    void
    windowIconified(WindowEvent e)
              تنتقل النافذة من الحالة العادية إلى الحالة المصغرة
    		 
    void
    windowOpened(WindowEvent e)
              تصبح النافذة مرئية لأول مرة
    		 

    وبالتالي، هناك سبعة أحداث يمكن إدارتها. تتلقى جميع برامج الإدارة كمعلمة كائن من النوع WindowEvent الذي نتجاهله في الوقت الحالي. الحدث الذي يهمنا هنا هو إغلاق النافذة، وهو حدث يجب معالجته بواسطة الطريقة windowClosing. لإدارة هذا الحدث، يمكننا إنشاء كائن Windowlistener باستخدام فئة مجهولة بالطريقة التالية:

    
   // إنشاء مدير أحداث
   WindowListener win=new WindowListener(){
     public void windowActivated(WindowEvent e){}
     public void windowClosed(WindowEvent e){}
     public void windowClosing(WindowEvent e){System.exit(0);}
     public void windowDeactivated(WindowEvent e){}
     public void windowDeiconified(WindowEvent e){}
     public void windowIconified(WindowEvent e){}
     public void windowOpened(WindowEvent e){}
   };//تعريف win

    يجب أن يحدد مدير الأحداث لدينا الذي ينفذ واجهة WindowListener الطرق السبع لهذه الواجهة. وبما أننا لا نريد سوى إدارة إغلاق النافذة، فإننا نحدد الكود فقط للطريقة windowClosing. عندما تحدث الأحداث الأخرى، سيتم إخطارنا بها ولكننا لن نقوم بأي شيء. ماذا سنفعل عندما يتم إخطارنا بأن النافذة قيد الإغلاق (windowClosing)؟ سنقوم بإيقاف التطبيق:

    
     public void windowClosing(WindowEvent e){System.exit(0);}

    لدينا هنا كائن قادر على إدارة أحداث النافذة بشكل عام. كيف نربطه بنافذة معينة؟ تحتوي الفئة JFrame على طريقة addWindowListener(WindowListener win) التي تسمح بربط مدير أحداث "نافذة" بنافذة معينة. وهكذا هنا، في منشئ النافذة سنكتب:

    
   // إنشاء مدير أحداث
   WindowListener win=new WindowListener(){
     public void windowActivated(WindowEvent e){}
     public void windowClosed(WindowEvent e){}
     public void windowClosing(WindowEvent e){System.exit(0);}
     public void windowDeactivated(WindowEvent e){}
     public void windowDeiconified(WindowEvent e){}
     public void windowIconified(WindowEvent e){}
     public void windowOpened(WindowEvent e){}
   };//تعريف win
    // سيقوم مدير الأحداث هذا بإدارة أحداث النافذة الحالية
   this.addWindowListener(win);

    البرنامج الكامل هو كما يلي:

    تحتوي الحزمة java.awt.event على واجهة WindowListener. عند تشغيل هذا البرنامج وإغلاق النافذة التي ظهرت، نلاحظ في نافذة DOS التي تم تشغيل البرنامج منها، انتهاء تشغيل البرنامج، وهو ما لم يكن موجودًا من قبل.

    في برنامجنا، يعد إنشاء الكائن المسؤول عن إدارة أحداث النافذة أمرًا ثقيلًا بعض الشيء، حيث نضطر إلى تعريف طرق حتى للأحداث التي لا نريد إدارتها. في هذه الحالة، بدلاً من استخدام الواجهة WindowListener، يمكننا استخدام الفئة WindowAdapter. هذه الفئة تنفذ الواجهة WindowListener، مع سبع طرق فارغة. من خلال اشتقاق الفئة WindowAdapter وإعادة تعريف الطرق التي تهمنا فقط، نصل إلى نفس النتيجة التي نحصل عليها مع الواجهة WindowListener ولكن دون الحاجة إلى تعريف الطرق التي لا تهمنا. تسلسل

    • تعريف معالج الأحداث
    • ربط المعالج بالنافذة

    يمكن أن تتم بالطريقة التالية في مثالنا:

    
   // إنشاء مدير أحداث
   WindowAdapter win=new WindowAdapter(){
     public void windowClosing(WindowEvent e){System.exit(0);}
   };//تعريف win
   // سيتولى مدير الأحداث هذا إدارة أحداث النافذة الحالية
   this.addWindowListener(win);

    5.1.3. نموذج مع زر

    لنضف الآن زرًا إلى نافذتنا:

    
// الفئات المستوردة
import javax.swing.*;
import java.awt.*;
import java.io.*;
import java.awt.event.*;

// فئة النموذج
 public class form3 extends JFrame {
 
     // زر
  JButton btnTest=null;
  Container conteneur=null;
  
  // المنشئ
  public form3() {
     // عنوان النافذة
    this.setTitle("Formulaire avec bouton");
     // أبعاد النافذة
    this.setSize(new Dimension(300,100));
    // إنشاء مدير أحداث
    WindowAdapter win=new WindowAdapter(){
     public void windowClosing(WindowEvent e){System.exit(0);}
    };//تعريف win
     // سيقوم مدير الأحداث هذا بإدارة أحداث النافذة الحالية
    this.addWindowListener(win);
     // نسترد حاوية النافذة
    conteneur=this.getContentPane();
     // نختار مدير تنسيق المكونات في هذا الحاوية
    conteneur.setLayout(new FlowLayout());
    // يتم إنشاء زر
    btnTest=new JButton();
    // يتم تحديد تسميته
    btnTest.setText("Test");
    // يتم إضافة الزر إلى الحاوية
    conteneur.add(btnTest);
  }//منشئ
  
  // وظيفة الاختبار
 public static void main(String[] args) {
    // عرض النموذج
   new form3().setVisible(true);
}//main
}//الفئة

    تحتوي نافذة JFrame على حاوية يمكن وضع المكونات الرسومية فيها (زر، مربعات اختيار، قوائم منسدلة، ...). هذه الحاوية متاحة عبر طريقة getContentPane من فئة JFrame:

    
  Container conteneur=null;
..........
     // استرداد حاوية النافذة
    conteneur=this.getContentPane();

    يتم وضع كل مكون في الحاوية بواسطة الطريقة add من الفئة Container. وبالتالي، لوضع المكون C في الكائن conteneur السابق، سنكتب:

    conteneur.add(C)

    أين يتم وضع هذا المكون في الحاوية؟ توجد العديد من أدوات إدارة تخطيط المكونات التي تحمل الاسم XXXLayout، حيث XXX يساوي على سبيل المثال Border، Flow، ... لكل مدير تخطيط خصائصه الخاصة. على سبيل المثال، يقوم المدير FlowLayout بترتيب المكونات في صفوف بدءًا من أعلى النموذج. وعندما يتم ملء صف ما، يتم وضع المكونات في الصف التالي. لربط مدير التنسيق بنافذة JFrame، يتم استخدام الطريقة setLayout من الفئة JFrame بالشكل التالي:

        setLayout(objet XXXLayout);

    5.6. كتابة التطبيقات الصغيرة

    5.6.1. مقدمة

    عند كتابة تطبيق بواجهة رسومية، من السهل تحويله إلى applet. عند تخزينه على جهاز A، يمكن تنزيله بواسطة متصفح ويب من جهاز B عبر الإنترنت. وبذلك يتم مشاركة التطبيق الأصلي بين العديد من المستخدمين، وهذا هو الهدف الرئيسي من تحويل التطبيق إلى تطبيق صغير. ومع ذلك، لا يمكن تحويل أي تطبيق بهذه الطريقة: حتى لا يضر المستخدم الذي يستخدم تطبيقًا صغيرًا في متصفحه، فإن بيئة التطبيق الصغير خاضعة للوائح:

    • لا يمكن لبرنامج applet القراءة أو الكتابة على قرص المستخدم
    • ولا يمكنها التواصل إلا مع الجهاز الذي تم تنزيلها منه بواسطة المتصفح.

    هذه قيود صارمة. فهي تعني، على سبيل المثال، أن أي تطبيق يحتاج إلى قراءة معلومات من ملف أو قاعدة بيانات سيتعين عليه طلبها عبر تطبيق وسيط موجود على الخادم الذي تم تنزيله منه.

    الهيكل العام لتطبيق ويب بسيط هو كما يلي:

    • يطلب العميل مستندًا HTML من خادم الويب، عادةً باستخدام متصفح. قد يحتوي هذا المستند على تطبيق صغير يعمل كتطبيق رسومي مستقل داخل المستند HTML المعروض بواسطة متصفح العميل.
    • يمكن أن يكون لهذا التطبيق الصغير حق الوصول إلى البيانات، ولكن فقط تلك الموجودة على خادم الويب. ولن يكون له حق الوصول إلى موارد الجهاز العميل الذي يقوم بتشغيله، ولا إلى موارد الأجهزة الأخرى على الشبكة بخلاف الجهاز الذي تم تنزيله منه.

    5.6.2.2. تشغيل تطبيق صغير: الطرق init و start و stop

    عندما يقوم متصفح بتحميل تطبيق صغير، فإنه يستدعي ثلاث طرق منه:

    init
    يتم استدعاء هذه الطريقة عند التحميل الأولي للتطبيق الصغير. لذلك، سنضع فيها التهيئات اللازمة للتطبيق.
    start
    يتم استدعاء هذه الطريقة في كل مرة يصبح فيها المستند الذي يحتوي على التطبيق الصغير هو المستند الحالي للمتصفح. وبالتالي، عندما يقوم المستخدم بتحميل تطبيق صغير، يتم تنفيذ طريقتي init و start بهذا الترتيب. وعندما يغادر المستخدم المستند لعرض مستند آخر، يتم تنفيذ طريقة stop. وعندما يعود إليه لاحقًا، يتم تنفيذ طريقة start.
    stop
    يتم استدعاء هذه الطريقة في كل مرة يغادر فيها المستخدم المستند الذي يحتوي على التطبيق الصغير.

    بالنسبة للعديد من التطبيقات الصغيرة، لا يلزم سوى استخدام طريقة init. أما طريقتا start و stop فلا تكونان ضروريتين إلا إذا كان التطبيق يشغل مهام (خيوط) تعمل بشكل متوازٍ ومستمر، غالبًا دون علم المستخدم. وعندما يغادر المستخدم المستند، يختفي الجزء المرئي من التطبيق، لكن هذه المهام التي تعمل في الخلفية تستمر في العمل. وغالبًا ما يكون ذلك غير ضروري. لذلك، نستفيد من استدعاء المتصفح لطريقة stop لإيقافها. إذا عاد المستخدم إلى المستند، نستفيد من استدعاء المتصفح لطريقة start لإعادة تشغيلها.

    لنأخذ على سبيل المثال تطبيق صغير يحتوي على ساعة في واجهته الرسومية. يتم الحفاظ على هذه الساعة بواسطة مهمة خلفية (خيط). عندما يغادر المستخدم صفحة التطبيق الصغير في المتصفح، لا فائدة من الحفاظ على الساعة التي أصبحت غير مرئية: في طريقة stop الخاصة بالتطبيق الصغير، سنوقف الخيط الذي يدير الساعة. وفي طريقة start، سنعيد تشغيله حتى عندما يعود المستخدم إلى صفحة التطبيق الصغير، يجد ساعة تعمل بالوقت الصحيح.

    5.6.5. الوصول إلى الموارد البعيدة من تطبيق صغير

    تستخدم العديد من التطبيقات المعلومات الموجودة في الملفات أو قواعد البيانات. وقد أشرنا إلى أن التطبيق الصغير لا يمكنه الوصول إلى موارد الجهاز الذي يتم تشغيله عليه. وهذا إجراء منطقي. وإلا يكفي كتابة تطبيق صغير لـ"التجسس" على القرص الخاص بمن يقومون بتحميله. ومع ذلك، يمكن للتطبيق الصغير الوصول إلى موارد الخادم الذي تم تنزيله منه، مثل الملفات. وهذا ما سنراه الآن.

    5.6.5.1. الفئة URL

    يمكن لأي تطبيق Java قراءة ملف موجود على جهاز في الشبكة بفضل الفئة java.net.URL (URL=Uniform Resource Locator). تحدد فئة URL موردًا على الشبكة، والجهاز الذي يوجد عليه، بالإضافة إلى البروتوكول ومنفذ الاتصال الذي يجب استخدامه لاسترداده بالشكل التالي:

    البروتوكول:المنفذ//الجهاز/الملف

    وبالتالي، يشير URL http://www.ibm.com/index.html إلى الملف index.html الموجود على الجهاز www.ibm.com. ويمكن الوصول إليه عبر بروتوكول http. لم يتم تحديد المنفذ: سيستخدم المتصفح المنفذ 80 الذي هو المنفذ الافتراضي لخدمة http.

    دعونا نستعرض بالتفصيل بعض عناصر الفئة URL:

    public URL(String spec)
    ينشئ مثيلًا لـ URL من سلسلة من النوع "protocol:port//machine/file" - يطلق استثناءً إذا كانت صيغة السلسلة لا تتوافق مع URL
      
    public String getFile()
    يسمح بالحصول على حقل الملف من السلسلة "protocol:port//machine/file" من URL
      
    public String getHost()
    يسمح بالحصول على حقل الجهاز من السلسلة "بروتوكول:منفذ//جهاز/ملف" من URL
      
    public String getPort()
    يسمح بالحصول على حقل المنفذ من السلسلة "بروتوكول:منفذ//جهاز/ملف" من URL
      
    public String getProtocol()
    يسمح بالحصول على حقل البروتوكول من السلسلة "protocole:port//machine/fichier" من URL
      
    public URLConnection openConnection()
    يفتح الاتصال بالجهاز البعيد getHost() على منفذه getPort() وفقًا لبروتوكول getProtocol() بهدف قراءة الملف getFile(). يلقي باستثناء إذا تعذر فتح الاتصال
      
    public final InputStream openStream()
    اختصار لـ openConnection().getInputStream(). يسمح بالحصول على دفق إدخال يمكن من خلاله قراءة محتوى الملف getFile(). يطلق استثناءً إذا تعذر الحصول على الدفق
      
    public String toString()

    • public URL(String spec) لتحديد الملف المراد استغلاله
    • public final InputStream openStream() لاستخدامه
