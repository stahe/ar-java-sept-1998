    6.2.2. مرحلة الاتصال

    لاستخدام قاعدة بيانات، يجب أن يقوم تطبيق Java أولاً بمرحلة الاتصال. ويتم ذلك باستخدام طريقة الفئة التالية:

    Connection DriverManager.getConnection(String URL, String id, String mdp)

    مع

    DriverManager: فئة Java تحتوي على قائمة برامج التشغيل المتاحة للتطبيق

    Connection: فئة Java تربط بين التطبيق وقاعدة البيانات، والتي من خلالها يقوم التطبيق بإرسال طلبات SQL إلى قاعدة البيانات وتلقي النتائج

    URL: الاسم الذي يحدد قاعدة البيانات. هذا الاسم مشابه لـ URL على الإنترنت. ولهذا السبب فهو جزء من فئة URL. ومع ذلك، لا يتدخل الإنترنت هنا بأي شكل من الأشكال. يكون شكل URL كما يلي:

    jdbc:nom_du_pilote:nom_de_la_source;param=val1;param2=val2

    في أمثلةنا التي سنستخدم فيها برامج تشغيل ODBC حصريًا، يُسمى برنامج التشغيل odbc. يتكون الجزء الثالث من URL من اسم المصدر مع المعلمات المحتملة. في أمثلةنا، ستكون هذه مصادر ODBC معروفة للنظام. وبالتالي، فإن URL لمصدر البيانات Articles المحدد سابقًا سيكون

    jdbc:odbc:Articles

    id: هوية المستخدم (login)

    mdp: كلمة مرور المستخدم (password)

    باختصار، يتصل البرنامج بقاعدة بيانات:

    • يتم تحديدها باسم (URL)
    • تحت هوية مستخدم (id, mdp)

    إذا كانت هذه المعلمات الثلاثة صحيحة، وإذا كان هناك برنامج تشغيل قادر على ضمان اتصال تطبيق Java بقاعدة البيانات المحددة، يتم إجراء اتصال بين تطبيق Java وقاعدة البيانات. ويتم تجسيد هذا الاتصال للبرنامج من خلال كائن من النوع Connection الذي توفره الفئة DriverManager. نظرًا لأن هذا الاتصال قد يفشل لأسباب مختلفة، فمن المحتمل أن يطلق استثناءً. لذلك سنكتب:

    
    Connection connexion=null;
    URL base=...;
    String id=...;
    String mdp=...;
try{
        connexion=DriverManager.getConnection(base,id,mdp);
} catch (Exception e){
        // معالجة الاستثناء
}

    لكي يكون الاتصال بقاعدة البيانات ممكنًا، يجب توفر برنامج التشغيل المناسب. في أمثلةنا، سيكون برنامج التشغيل ODBC قادرًا على إدارة قاعدة البيانات المطلوبة. وإذا كان يجب أن يكون هذا البرنامج التشغيلي متاحًا في قائمة برامج التشغيل ODBC الموجودة على الجهاز، فيجب أيضًا توفر الفئة JAVA التي ستعمل كواجهة تواصل معه. وللقيام بذلك، سيطلب التطبيق الفئة اللازمة له بالطريقة التالية:

        Class.forName(String nomClasse)

    لا ترتبط الفئة Class بأي شكل من الأشكال بواجهة JDBC. إنها فئة عامة لإدارة الفئات. تسمح طريقتها الثابتة forName بتحميل فئة ديناميكيًا وبالتالي الاستفادة من سماتها وطرقها الثابتة. تسمى الفئة التي تشكل واجهة مع برامج التشغيل ODBC لـ MS Windows « sun.jdbc.odbc.JdbcOdbcDriver ». لذلك سنكتب (قد تولد الطريقة استثناءً):

    try{
    Class.forName(« sun.jdbc.odbc.JdbcOdbcDriver ») ;
} catch (Exception e){
    // معالجة الاستثناء (فئة غير موجودة)
}

    توجد الفئات اللازمة للواجهة JDBC في الحزمة java.sql. لذلك سنكتب في بداية البرنامج:

        import java.sql.*;

    6.2.3. إرسال الاستعلامات إلى قاعدة البيانات

    تسمح واجهة JDBC بإرسال استعلامات SQL إلى قاعدة البيانات المتصلة بتطبيق Java وكذلك معالجة نتائج هذه الاستعلامات. لغة SQL (لغة الاستعلام الهيكلية) هي لغة استعلامات موحدة لقواعد البيانات العلائقية. وتتميز بعدة أنواع من الاستعلامات:

    • استعلامات الاستعلام عن قاعدة البيانات (SELECT)
    • استعلامات تحديث قاعدة البيانات (INSERT، DELETE، UPDATE)
    • طلبات إنشاء/حذف الجداول (CREATE، DELETE)

    نفترض هنا أن القارئ على دراية بأساسيات لغة SQL.

    6.2.3.1. فئة Statement

    لإرسال أي استعلام SQL إلى قاعدة بيانات، يجب أن يتوفر للتطبيق Java كائن من نوع Statement. سيخزن هذا الكائن، من بين أمور أخرى، نص الاستعلام. ويرتبط هذا الكائن بالضرورة بالاتصال الجاري. لذلك، فإن إحدى طرق الاتصال الذي تم إنشاؤه هي التي تسمح بإنشاء الكائنات Statement اللازمة لإرسال الاستعلامات SQL. إذا كان connexion هو الكائن الذي يمثل الاتصال بقاعدة البيانات، يتم الحصول على كائن Statement بالطريقة التالية:

        Statement requete=connexion.CreateStatement();

    بمجرد الحصول على كائن Statement، يمكن إصدار طلبات SQL. ويتم ذلك بطريقة مختلفة حسب ما إذا كان الطلب طلب استعلام أو تحديث للقاعدة.

    6.2.3.2. إرسال طلب استعلام عن قاعدة البيانات

    عادةً ما يكون طلب الاستعلام من النوع التالي:

        select col1, col2,... from table1, table2,...
    where condition
    order by expression
    ...

    الكلمات الرئيسية في السطر الأول هي فقط التي تعتبر إلزامية، أما البقية فهي اختيارية. وهناك كلمات رئيسية أخرى غير مذكورة هنا.

    1. يتم إجراء عملية ربط مع جميع الجداول الموجودة بعد الكلمة الرئيسية from
    2. يتم الاحتفاظ فقط بالأعمدة الموجودة بعد الكلمة الرئيسية select
    3. يتم الاحتفاظ فقط بالصفوف التي تستوفي شرط الكلمة الرئيسية where
    4. تشكل الأسطر الناتجة المرتبة وفقًا للتعبير الوارد في الكلمة الرئيسية order by نتيجة الاستعلام.

    نتيجة select هي جدول. إذا أخذنا الجدول ARTICLES السابق بعين الاعتبار وأردنا الحصول على أسماء المنتجات التي يقل مخزونها الحالي عن الحد الأدنى، فسنكتب: select name from products where stock_actu<stock_mini. إذا أردنا ترتيبها أبجديًا حسب الأسماء، فسنكتب: select name from items where stock_actu<stock_mini order by name

    لتنفيذ هذا النوع من الاستعلامات، توفر الفئة Statement الطريقة executeQuery:

        ResultSet executeQuery(String requête)

    حيث requête هو نص الاستعلام SELECT المراد إرساله.

    وبالتالي، إذا كان

    • كان connexion هو الكائن الذي يمثل الاتصال بقاعدة البيانات
    • Statement s=connexion.createStatement() ينشئ الكائن Statement الضروري لإرسال الاستعلامات SQL
    • ResultSet rs=s.executeQuery(« select name from articles where stock_actu<stock_mini ») تنفذ استعلام select وتعيّن صفوف نتائج الاستعلام إلى كائن من النوع ResultSet.

    6.2.3.3. الفئة ResultSet: نتيجة استعلام select

    يمثل كائن من النوع ResultSet جدولًا، أي مجموعة من الصفوف والأعمدة. في لحظة معينة، لا يمكن الوصول إلا إلى صف واحد من الجدول يُسمى الصف الحالي. عند الإنشاء الأولي لـ ResultSet، يكون الصف الحالي هو الصف رقم 1 إذا لم يكن ResultSet فارغًا. للانتقال إلى السطر التالي، تتوفر للفئة ResultSet الطريقة next:

        boolean next()

    تحاول هذه الطريقة الانتقال إلى السطر التالي من ResultSet وتُرجع true في حالة نجاحها، وfalse في حالة الفشل. في حالة النجاح، يصبح السطر التالي هو السطر الحالي الجديد. يتم فقدان السطر السابق ولا يمكن الرجوع للخلف لاستعادته. تحتوي جدول ResultSet على أعمدة col1 و col2 و... لاستخدام الحقول المختلفة في السطر الحالي، تتوفر الطرق التالية:

    Type getType("coli")

    للحصول على الحقل « coli » من السطر الحالي. Type يشير إلى نوع الحقل coli. غالبًا ما يتم استخدام الطريقة getString على جميع الحقول، مما يسمح بالحصول على محتوى الحقل كسلسلة أحرف. ثم يتم التحويل إذا لزم الأمر. إذا لم يكن اسم العمود معروفًا، يمكن استخدام الطرق 

    Type getType(i)

    حيث i هو مؤشر العمود المطلوب (i>=1).

    6.2.3.4. مثال أول

    فيما يلي برنامج يعرض محتوى قاعدة البيانات ARTICLES التي تم إنشاؤها مسبقًا:

    6.2.3.5. الفئة ResultSetMetadata

    في المثال السابق، نعرف أسماء أعمدة ResultSet. إذا لم نكن نعرفها، فلا يمكننا استخدام الطريقة getType(nom_colonne). بدلاً من ذلك، سنستخدم getType(رقم العمود). ومع ذلك، للحصول على جميع الأعمدة، يجب أن نعرف عدد الأعمدة في ResultSet الذي تم الحصول عليه. لا توفر لنا الفئة ResultSet هذه المعلومات. بل توفرها لنا الفئة ResultSetMetaData. وبشكل عام، توفر لنا هذه الفئة معلومات عن بنية الجدول، أي عن طبيعة أعمدةه.

    يمكن الوصول إلى المعلومات حول بنية ResultSet عن طريق إنشاء مثيل لكائن ResultSetMetaData أولاً. إذا كان RS هو ResultSet، يتم الحصول على ResultSetMetaData المرتبط به عن طريق:

        RS.getMetaData()

    تجدر الإشارة إلى طريقتين مفيدتين في الفئة ResultSetMetaData:

    1. int getColumnCount() التي تعطي عدد أعمدة ResultSet
    2. String getColumnLabel(int i) التي تعطي اسم العمود i في ResultSet (i>=1)

    6.2.3.7. إرسال طلب تحديث قاعدة البيانات

    يسمح كائن من النوع Statement بتخزين طلبات SQL. الطريقة التي يستخدمها هذا الكائن لإصدار طلبات تحديث SQL (INSERT، UPDATE، DELETE) لم تعد الطريقة executeQuery التي تمت دراستها سابقًا، بل الطريقة executeUpdate:

        int executeUpdate(String requête)

    يكمن الاختلاف في النتيجة: في حين أن executeQuery كانت تُرجع جدول النتائج (ResultSet)، فإن executeUpdate تُرجع عدد الأسطر المتأثرة بعملية التحديث.

    }//الحساب
}//الفئة

    • إذا كانت الإجابة "لا" (=vbno)، يتم تعيين cancel إلى -1 ويتم الخروج من الإجراء form_unload. يشير cancel إلى -1 إلى رفض إغلاق النافذة.
    • إذا كانت الإجابة "نعم" (=vbyes)، يتم إغلاق قاعدة البيانات (data1.recordset.close، data1.database.close).
    الجزء 2 - إدارة القوائم

    هنا، نهتم بتفعيل/تعطيل القوائم. بعد كل عملية تغير السجل الحالي، سنستدعي إجراءً يمكن أن نسميه Oueston. سيتحقق هذا الإجراء من الشروط التالية:

    . إذا كان الملف فارغًا،

    • سنقوم بتعطيل قوائم "استعراض" و"تحرير/حذف"،
    • ونسمح بالبقية

    . إذا كانت البطاقة الحالية هي البطاقة الأولى،

    • يتم تعطيل "استعراض/السابق"
    • ويسمح بالباقي

    . إذا كانت البطاقة الحالية هي الأخيرة،

    • يتم تعطيل "تصفح/التالي"
    • السماح بالباقي
    الجزء 3 - إدارة المتغير الأفقي

    يحتوي المتغير الأفقي على ثلاثة حقول مهمة:

    • min: قيمته الدنيا
    • max: قيمته القصوى
    • القيمة: قيمته الحالية

    تهيئة المحرك

    عند التحميل (form_load)، سيتم تهيئة المحرك المتغير على النحو التالي:

    • min=0
    • max=data1.recordset.recordcount-1
    • القيمة=1

    تجدر الإشارة إلى أنه فور فتح قاعدة البيانات (data1.refresh)، يكون عدد السجلات في الجدول الممثل بـ data1.recordset.recordcount غير صحيح. يجب الانتقال إلى نهاية الجدول (MoveLast)، ثم العودة إلى بداية الجدول (MoveFirst) حتى يصبح صحيحًا.

    التأثير المباشر على المحرك

    يمثل موضع مؤشر المحول الموضع في الجدول.

    عندما يقوم المستخدم بتعديل المتغير (المسمى هنا position)، يتم تشغيل الحدث position_change. في هذا الحدث، سنقوم بتغيير السجل الحالي في الجدول بحيث يعكس التغيير الذي تم إجراؤه على المنزلق. للقيام بذلك، سنستخدم الحقل absoluteposition في data1.recordset. عند تعيين القيمة i لهذا الحقل، تصبح البطاقة رقم i في الجدول هي البطاقة الحالية. يتم ترقيم السجلات بدءًا من 0، وبالتالي يكون لها رقم في النطاق [0,data1.recordset.recordcount-1]. في الإجراء position_change، يكفي أن نكتب

        data1.recordset.absoluteposition=position.value

    حتى تعكس البطاقة الحالية المعروضة على النموذج التغيير الذي تم إجراؤه على المحول.

    وبعد ذلك، سنستدعي إجراء Oueston لتحديث القوائم.

    تحديث المحول

    نظرًا لأن موضع مؤشر المتغير يجب أن يعكس الموضع في الجدول، يجب تحديث قيمة المتغير في كل مرة يحدث فيها تغيير في السجل الحالي في الجدول، ناتج عن أحد القوائم. وبما أن كل قائمة تستدعي إجراء Oueston، فمن الأفضل وضع هذا التحديث أيضًا في هذا الإجراء. يكفي كتابة ما يلي هنا:

        position.value=data1.recordset.absoluteposition
    الجزء 4 - خيار البحث

    نضيف خيار "تصفح/بحث" الذي يهدف إلى السماح للمستخدم بعرض عنصر يحدد رمزه.

    عند تنشيط هذا الخيار، تحدث التسلسلات التالية:

    • ننتقل إلى "إضافة سجل" (Addnew)، وذلك لغرض وحيد هو عدم تعديل السجل الحالي الذي كنا عليه عند تنشيط الخيار،
    • يتم السماح بالإدخال في حقل الرمز ومسح محتوى حقل السجل،
    • يتم تعطيل القوائم وعرض الأزرار OK و"إلغاء"
    • عندما يضغط المستخدم على OK، يتعين علينا البحث عن السجل المطابق للرمز الذي أدخله المستخدم. لكن الإجراء OK_click يُستخدم بالفعل في خياري "تصفح/إضافة" و"تصفح/تعديل". للتمييز بين هذه الحالات، يتعين علينا إدارة متغير عام سنسميه هنا "الحالة" وسيكون له ثلاث قيم محتملة: "إضافة" و"تعديل" و"بحث". ستستخدم الإجراءات المرتبطة بالأزرار OK و"إلغاء" هذا المتغير لمعرفة السياق الذي يتم استدعاؤها فيه.
    • إذا كانت قيمة "الحالة" هي "البحث"، ففي الإجراء المرتبط بـ OK،
      • يتم إلغاء عملية addnew (data1.recordset.cancelupdate) لأنه لم يكن هناك نية لإضافة سجل. تجدر الإشارة إلى أن السجل الحالي يعود إلى ما كان موجودًا على الشاشة قبل عملية التصفح/البحث.
      • يتم إنشاء معيار البحث المرتبط بالرمز ويتم بدء البحث (data1.recordset.findfirst معيار)،
      • إذا فشل البحث (data1.recordset.nomatch=true)، يتم إخطار المستخدم بذلك، ثم نعود إلى وضع الإضافة (addnew) ونخرج من الإجراء OK. سيتعين على المستخدم إعادة كتابة رمز جديد أو اختيار خيار "إلغاء".
      • إذا نجح البحث، تصبح السجلات التي تم العثور عليها هي السجلات الحالية الجديدة. يتم إعادة عرض القوائم، وإخفاء الأزرار OK/إلغاء، ومنع الإدخال في حقل الرمز، ثم الخروج من الإجراء.
    • . إذا كانت الحالة "بحث"، في الإجراء المرتبط بـ "إلغاء"،
      • يتم إلغاء عملية addnew (data1.recordset.cancelupdate). ثم يتم العودة تلقائيًا إلى السجل الحالي قبل عملية "تصفح/بحث".
      • إعادة عرض القوائم، وإخفاء الأزرار OK/إلغاء، ومنع الإدخال في حقل الرمز، ثم الخروج من الإجراء.
    الجزء 5 - إدارة الرمز

    يجب تحديد كل منتج بشكل فريد بواسطة رمزه. تأكد من أنه في خيار "تصفح/إضافة"، يتم رفض الإضافة إذا كان السجل المراد إضافته يحتوي على رمز منتج موجود بالفعل في الجدول.
